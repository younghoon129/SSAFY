## 포트폴리오 양식
- PPT(추천)
    - 장점
        - 레이아웃, PPT 디자인, 다양한 도구 활용가능
        - 시각적으로 직관적 자료로 만들기 용이
        - PDF 변환 용이
    - 단점
        - 실시간 상호작용이나 동적인 콘텐츠를 담기 어려움
- Github
    - 장점
        - 프로젝트의 실제 코드를 업로드하고 관리가능
        - 작업 히스토리 통해 개발과정 보여주기 가능
    - 단점
        - 디자인 아쉬울 수 있음
- notion(비추천)
    - 장점
        - 텍스트, 이미지, 동영상, 링크 등을 통합하여 정리 가능
        - 실시간 수정과 공유가 쉬움
        - 데이터베이스나 목차를 활용해서 체계적으로 구성 가능
    - 단점
        - 오프라인 환경에서는 접근 어려움, 활용하기 시간 필요
        - Github 처럼 코드 자체 보여주기 한계
- word
    - 상세설명, 기술 문서 등을 작성하기 용이
    - 단순하고 PDF 변환도 쉬움

- 문제 해결 및 기술 선정 이유 작성 필수

## 포트폴리오 핵심 구성요소 - 프로필
- 본인이 어필하고 싶은 강점을 중심으로 작성
    - 구체적인 방향성을 제시: 사용자 중심, 기술적 전문성, 성장, 열정, 목표 등
    - 짧게 핵심을 담아서 작성
    - 너무 당연하거나 누구나 사용할 수 있는 표현보다는 자신만의 특성을 보여줄 수 있는 표현 사용

- 자기소개: 슬로건과 연결하여 나의 직무, 경험, 관심사를 포함하여 간략히 설명
    - 자신이 특화되어 있는 직무가 드러나도록 작성
    - 관심 있는 기술 영역이 드러나도록 작성
    - 지원하는 기업의 인재상과 비전에 맞춰 조금씩 수정하여 작성

- 기술스택: 자신이 다룰 수 있는 기술과 숙련도를 명확히 작성
    - 희망 직무와 연관된 보유 기술 또는 자신 있는 기술을 우선하여 작성
    - 기술을 카테고리화(언어, 데이터베이스 등) 하여 제시
    - 각 기술의 숙련도를 시각화하여 제시
    - 보유한 기술로 구현했거나 구현 가능한 사항을 함께 서술

## 포트폴리오 핵심 구성요소 - 이력사항
- 기본정보: 개인정보, 개발자 역량을 알 수 있는 정보
    - 지원서에도 작성하므로 최소한의 정보만 작성
    - 기술역량 확인 링크: 깃허브, 블로그
    - 자격사항, 특허, 논문 등

- 어필경험: 교육사항, 수상내역, 기타 어필 경험 작성
    - 교육 사항
        - 주요 전공 과목
        - 온라인 학습, 부트캠프 등
        - 구체적인 참여 연도, 기간 표시
    - 수상 내역
        - 수상 내역은 프로젝트와 연결 가능성 강조
        - 자격증은 공식 몇잉과 발급 연도, 유효 기간 명시
    - 기타 경험
        - 인턴, 동아리, 오픈 소스 기여 등

## 포트폴리오 핵심 구성요소 - 프로젝트 소개
- 핵심: 프로젝트 경험을 통해 개발자로서의 경험, 역량, 고민 내용, 성과 등을 어필
    - 프로젝트 개요, 담당 역할 및 기여, 구현 사항, 문제 해결, 프로젝트 성과&결과, 회고
    - 프로젝트 개요
        - 프로젝트 명은 짧고 부르기 쉬운 별도의 명칭으로 기술
        - 프로젝트 목적을 작성
            - 무엇을, 왜, 어떠한 의도를 가지고 개발했는지 설명
        - 프로젝트 진행 기간, 진행 인원, 개발 환경
    - 담당 역할/기여
        - 팀에서 맡은 역할과 기여를 구체적으로 기술
            - 프로젝트에서 나의 포지션 기재
            - 내가 중점적으로 구현한 사항, 간접적으로 보탬이 된 점, 협업 차원에서 나의 역할 등 상세히 기재
            - 내가 생각하는 나의 기여도
        - 직접 구현하거나 기여한 기능 중심으로 기술
    
    - 구현 사항, 문제해결
        - 사용한 기술과 기술 선택 이유가 드러나도록 작성
            - 특정 구현을 위해 왜 그 기술스택을 활용하여 진행했는지 내용을 기재
        - 선택한 기술이 프로젝트에 어떻게 기여했는지 작성
        - 직접 수행한 작업 중심으로 구체적으로 제시
            - 개발 내용 작성 시 무엇을, 왜, 어떻게 개발했고 어떤 결과물이 나오게 되었는지를 구체적 서술
            - 구현기능 및 성능을 상세히 작성
        - 프로젝트를 진행하며 직면한 문제를 구체적으로 기술
            - 문제 내용, 원인, 원인 파악하기 위한 고민내용/방향 작성
        - 문제 해결하기 위해 적용한 방법 및 기술 구체적 설명
            - 파악한 원인을 해결하기 위한 접근 방법, 고민 내용과 함께 문제해결 방법 작성
        - 해결방법 및 기술 적용의 결과가 드러나도록 작성

    - 프로젝트 성과&결과, 회고
        - 구체적인 성과를 데이터 또는 수치화 하여 표현
            - 대외적인 성과, 구현 결과, 프로젝트를 통해 새롭게 알게 된 지식 또는 향상된 개발 역량 작성
        - 사용자 설문조사 결과나 피드백 활용
            - 신입 개발자로서 얼마나 더 성장할 수 있는 사람인지를 어필하는 것이 중요
        - 프로젝트를 통해 배운/성장한 점
            - 처음 마주한 문제나 기술 영역을 풀어나가는 방식, 꾸준하게 진행한 학습내용과 배운 내용에 대해 작성
            - 기술적 측면 뿐 아니라 협업을 하면서 팀 안에서 배우고 느낀 점도 함께 기술
        - 아쉬웠던 점, 문제점
            - 프로젝트를 마무리 한 후 아쉬웠던 점과 문제점 등을 정리해보고 지금이라면 어떻게 보완/개선해나갈 수 있을지를 기술

## 포트폴리오 작성 - Front-End
- 비주얼 & UI/UX 요소를 강조
    - 프로젝트의 화면 캡쳐를 포함하고 UI/UX 개선 과정을 설명
    - 포트폴리오 가독성 또한 타 직무에 비해 중요
    - 사용자 경험을 고려한 디자인 적용 사례와 피드백 반영 과정을 포함하면 가산점이 될 수 있음
- 반응형 웹과 성능 최적화 경험을 포함
    - 반응형 웹을 지원하기 위해 미디어 쿼리, flexbox, grid 활용 경험을 추가하는 것이 좋음
    - 최적화 기법을 반영한 경험
- 상태 관리 및 데이터 처리

- 프로젝트-듣공
    - 기여도 %로 수치화
    - 서비스 이해도 + UX 설계 능력 밸런스 잡기
    - 기능 설계 이유 답변 가능하면 좋음

## 포트폴리오 작성 - AI
- 모델 성능과 평가 지표를 포함
    - AI 모델의 성능을 평가하기 위한 정확도, 정밀도, 재현율 등의 지표를 포함
    - 단순한 성능 수치뿐 아니라, 모델을 개선하기 위해 적용한 기법과 그 효과를 설명하면 더욱 좋다
- 데이터 전처리 및 파이프라인 구축 경험을 강조
    - 데이터 정제(결측치 처리 이상치 제거, 스케일링) 과정을 설명하고, 이를 코드와 함께 제공하면 좋다
    - 데이터 수집, 처리, 모델 학습까지 이어지는 자동화된 파이프라인을 구축한 경험이 있다면 이를 포함
- 실제 적용 사례를 포함
    - AI 모델이 실제 서비스에서 활용된 사례를 설명
- 벡터화, 전후 차이 설명
- 트러블 슈팅
    - 문제 -> 원인 -> 해결방안
    - 성과 강조
    - 데이터 엔지니어링, AI 분야 사고력 강조
