# Kafka, MSA

## Kafka
- 파이프라인, 스트리밍 분석, 데이터 통합 및 미션 크리티컬
- 애플리케이션을 위해 설계된 고성능 분산 이벤트 스트리밍 플랫폼
- 카프카 구조
    - 클러스터 > 브로커 > 토픽 > 파티션 > 세그먼트로 구성
    - 프로듀서
        - 데이터를 발생
    - 컨슈머
        - 클러스터에서 가져온 데이터 처리
    - 클러스터
        - 프로듀서가 발행한 데이터를 안정적으로 관리
    

## MSA
- 하나의 큰 어플리케이션을 여러 개의 **작은 어플리케이션으로 쪼개어 변경과 조합이 가능**한 아키텍처
- 장점
    - 독립적으로 배포 가능
        - 독립적으로 개발하기 때문에 다른 서비스를 신경 쓰지 않아도 됨
        - 서로 다른 프로그래밍 언어나, DB 사용 가능
    - 한 서비스의 장애가 전체 시스템 장애로 전파되지 않음
    - 개별 서비스 단위로 새로운 기술 적용 가능
    - 서비스의 확장이 용이

- 설계 파이프라인
    - 도메인 중심 설계(Domain-Driven Design)
    - 단일 책임의 원칙을 따르자
    - 서비스는 독립적으로 배포되고 유지보수 될 수 있어야 함
    - 클라이언트 요청은 API 게이트웨이를 통해 여러 마이크로서비스로 라우팅
    - 이벤트 기반의 비동기 메시징을 사용하면 서비스 간 결합을 최소화하면서 확장성을 높일 수 있음 (Kafka 사용)

- 카프카 적용 시 고려할 사항
    - 토픽 설계
        - 적절한 파티션 수 설정
        - 너무 많으면 오버헤드 발생, 너무 적으면 확장성 문제 발생
    - 브로커 설정
        - 데이터 손실 방지를 위해 중복 설정 필요(각 메시지를 여러 브로커에 복제)
    - 장애 복구 및 신뢰성
        - 실패한 메시지 처리를 위해 재시도 로직을 설계 시 고려해야 함
        - 특정 기간 내에 처리되지 않은 메시지를 처리 방식을 고려해야 함
    - 모니터링
        - 클러스터의 상태를 모니터링 하기 위해 Prometheus+Grafana, ELK 등의 툴을 사용하기 위한 설계 고려해야 함
        - 로그를 중앙화 된 방식...
