# 테스트 방법론
- 단위 테스트
    - 가장 작은 범위를 테스트
    - 개별 함수, 메서드, 클래스, 컴포넌트 등의 동작 테스트
    - 실행하는데 가장 적은 비용
    - 가장 빈번하게 수행 가능한 테스트
- 통합 테스트
    - 두 개 이상의 모듈이 결합하여 동작을 잘 수행하는 지 테스트
- 시스템 테스트
    - 실제 유저가 애플리케이션을 사용하는 것과 유사한 환경을 구축한 후 실제 유저의 동작을 유사하게 테스트

## 테스트 할 때 고려할 점
- 시스템 테스트는 반드시 프로그램을 개발한 팀이나 프로그래머와는 무관한 그룹에 의해서 수행되어야 함
    - 개발자의 사심이 들어가 정확한 테스트가 어려운 경우가 있기 때문
- 타당하지 않고 예상치 못한 경우에 대해서도 테스트를 수행하라
    - 제품을 처음 사용하는 고객은 예측하지 못한 방법으로 사용 할 수 있음
- 오류가 남아있을 확률은 이미 발견된 오류의 수에 비례 함
    - 오류가 발생한 곳에는 다시 오류가 생길 가능성이 높으므로, QA입장에서는 중점적으로 확인할 필요가 있음
- 테스트 케이스를 체계적으로 관리
    - 효율 높아지고, 테스트 시간도 줄어 듦
- 각각의 테스트 결과를 철저하게 점검
    - 지속적으로 관리를 하라는 의미
- 와이파이, 오프라인, 인터넷 속도에 따라 기대 결과를 고려해야 함
- 유니티로 개발한 게임은 저사양 옵션이 추가 되어 있는지
- 저속 인터넷 환경에서 로딩에 문제가 없는 지 미리 파악
- 오프라인 상황에서 캐시를 통한 동작이나 네트워크 경고 팝업 창 등

## 테스트 종류와 도구
- 부하테스트
    - 웹 서비스가 일정한 사용자 수 또는 요청을 처리할 수 있는지를 평가하는 테스트
    - JMeter, Gatling, nGrinder, K6, LoadRunner(상용)
- 스트레스 테스트
    - 예상치를 초과하는 부하를 가하여 서비스의 한계를 측정하는 테스트
    - Locust(Python 기반), Tsung

## 모니터링 도구 종류
- 프로파일링 도구
    - 코드 레벨에서 애플리케이션의 성능을 분석하여 병목 지점을 파악하고 최적화
- 서버 성능의 병목
- 로깅 및 모니터링
    - 서버 로그 분석, 실시간 모니터링 도구를 사용하여 서버의 성능 지표를 추적
        - 매트릭 기반 Prometheus 모니터링, Grafana 사용하여 시각화
        - Nginx 웹서버의 접근 로그를 Logstash를 통해 Elasticsearch에 전송하고, Kibana를 사용하여 접근 로그의 IP 주소와 요청 URL에 대한 대시 보드 생성
        - 로그를 수집하는 Promtail, 수집된 로그를 저장하는 Loki, 저장된 로그를 시각화 하는 Grafana

## Sentry 에러 로그 분석
- 실시간 로그 취합 및 분석 도구, 모니터링 플랫폼
- 많은 회사에서도 도입하고 있는 검증된 툴로 프론트엔드, 백엔드, 안드로이드

## 테스트 결과 분석을 위한 중요 지표
- 응답 시간
    - 시스템이 요청에 응답하는 데 걸리는 시간
    - 응답 시간이 너무 길다면 시스템의 성능 저하를 나타냄
    - 평균 응답 시간과 최대 응답 시간을 비교 분석하는 것이 중요
- 처리량
- CPU 사용률
    - CPU가 얼마나 활용되고 있는지를 나타냄
    - CPU 사용률이 100%에 가까워진다면 CPU 병목 현상이 발생할 가능성이 높음
- 메모리 사용률
- 디스크 I/O
    - 쿼리문 개선한 경험 등
- 에러율
