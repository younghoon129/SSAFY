# Rendering
- 브라우저는 어떻게 동작하는가?
- 브라우저는 어떻게 웹 페이즈를 입히는가?

- 브라우저의 주요 기능
    - 사용자가 요청한 리소스(HTML, CSS, 이미지 등)를 서버로부터 가져와 해석하여 화면에 렌더링
    - JavaScript를 실행하고 동적인 사용자 인터페이스를 제공

- 브라우저의 구조
    - 사용자 인터페이스
    - 브라우저 엔진
    - 렌더링 엔진
    - 네트워킹
    - 자바 스크립트 엔진
    - UI 백엔드
    - 데이터 저장소

- 브라우저 통신 과정
    - URL 주소 입력
    - IP 찾기(DNS 서버)
    - HTTP(S) 요청/응답
    
- 브라우저 동작 과정

- 렌더링 방식
    - CSR(Client Side Rendering)
        - CSR은 클라이언트 쪽에서 발생. 즉, 서버는 요청을 받으면 클라이언트에 HTML과 JS를 보내줌. 클라이언트는 그것을 받아 렌더링 시작
        - 장점
            - 
        - 단점
            - SEO
    - SSR(Server Side Rendering)
        - 서버에서 JavaScript를 실행해 HTML을 생성
        - 장점
            - SEO 문제 보완
        - 단점
            - 초기 페이지 렌더링이 늦어질 수 있음

    - SSG(Static Site Generation)
        - 모든 페이지를 미리 렌더링해 사용자의 요청에 맞는 HTML을 응답
        - CDN 호스팅팅 또한 가능
        - 장점
            - CDN을 통해 쉽게 제공
            - SEO 문제 보완
        - 단점
            - 새로운 페이지가 필요한 경우 application을 새로 빌드해야 됨
    - ISR
        - 페이지 단위로 정적 생성 할 수 있음
        - 장점
            - SSG처럼 미리 렌더링하고 캐시하기 때문에 매우 굉장히 빠름
        - 내용 변경되어도 사이트 다시 배포하지 않아도 됨
