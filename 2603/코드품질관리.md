# 코드 품질 관리
- 소나큐브 이용하여 분석 

## 코드 커버리지
- 소프트웨어 테스트의 측정 항목 중 하나로, 테스트를 수행했을 때 얼마나 많은 코드가 실행되었는지를 나타내는 지표
- 작성된 코드 중 테스트가 실행된 코드의 비율을 측정하는 지표
- 블랙 박스 테스트
    - 사용자 관점의 테스트 방법
    - 내부 구조나 작동 원리를 모르는 상태에서 동작을 검사하는 방식
- 화이트 박스 테스트
    - 개발자 관점의 단위 테스트 방법
    - 내부 구조와 동작을 검사하는 테스트
- 백엔드
    - Jacoco + Gradle.kts 로 테스트 커버리지 확인
    - Jacoco: JVM 기반 언어
- 프론트엔드
    - Jest, Cypress 로 테스트

## 중복코드 분석
- 유지 보수가 어렵지 않도록 클린 코드로 리팩토링
- 코드작성, 테스트 코드 작성, 리팩토링 단계를 아주 작은 기능 단위로 반복
- DRY(Don't Repeat Yourself) 원칙을 활용
    - 동일한 코드가 여러 번 나오는 중복
        - 무분별하게 복사 + 붙여넣기 하다 보면 흔하게 발생하는 중복
        - 코드를 컴포넌트로 구성하여 중복을 줄일 수 있음
    - if /else if 문으로 불필요한 조건문이 반복되는 경우
        - switch/case 로 중복 줄이는 것(케바케일 수도)
    - 과도한 주석을 붙이는 경우
    - 주의점
        - 초기 단계나 소규모 개발에서는 다소 중복을 허용하고, 충분한 공통 패턴이 드러난 후에야 DRY를 적용해 추상화를 시작
        - 너무 엄격하게 적용 시 미래의 변경이 더 어려워질 수 있음
